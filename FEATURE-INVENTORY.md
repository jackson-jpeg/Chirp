# ChirpChirp — Feature Inventory (v1.0)

The v1 scope is a walkie-talkie for nearby devices. Five features, one
transport, no internet dependency. Everything below is shipped in 1.0;
anything not listed here does not exist in the codebase.

## Talk (Push-to-Talk)

- Hold-to-talk voice over MultipeerConnectivity (peer-to-peer Wi-Fi + Bluetooth)
- Opus-encoded audio, jitter-buffered playback (`AudioEngine`, `OpusCodec`,
  `JitterBuffer`)
- Distributed floor control — one speaker at a time, mesh-wide
  (`FloorMachine`, JSON `FloorControlMessage`)
- Multi-hop audio relay with TTL-bounded mesh packets (`MeshRouter`,
  `MeshPacket`)
- Live transcription of incoming audio, on-device (`LiveTranscription`,
  Speech framework)

## Messages (Channels + Text Chat)

- Channels: open or locked (invite code), created and joined locally
  (`ChannelManager`)
- Text chat with delivery ACKs, reactions, replies, typing indicators
  (`TextMessageService`)
- Image, file, and location attachments, chunked over the mesh
  (`FileTransferService`, `ImageCompressor`)
- Store-and-forward for peers that reconnect later (`StoreAndForwardRelay`)
- Message history persisted locally in GRDB (`MessageDatabase`)
- Quick replies (`QuickReply`)
- Friends list with proximity alerts (`FriendsManager`, `ProximityAlert`)

## Map

- Offline-capable map (MapLibre) with peer positions from mesh beacons
  (`GeoMapView`, `MeshBeacon`)
- Offline tile-region downloads (`OfflineMapManager`,
  `OfflineMapDownloadSheet`)
- Location shared only with nearby peers, only while the app is in use

## Voice Messages

- Recorded voice notes, queued and delivered over the mesh
  (`VoiceMessageQueue`, `VoiceNoteRecorder`)

## Settings

- Callsign (generated by `CallsignGenerator`, never the device name)
- Channel management, mesh diagnostics (`DiagnosticsView`)
- Behind the gear icon on the home toolbar — there is no More tab

## Cross-cutting

- **Transport**: MultipeerConnectivity only (`MultipeerTransport`)
- **Encryption**: messages are encrypted between channel members —
  AES-GCM under a shared per-channel key with epoch rotation
  (`ChannelCrypto`, KRO! rotation packets). This is shared-key encryption,
  not per-recipient end-to-end encryption, and every string in the app
  says so accordingly.
- **Identity**: Ed25519 signing keypair in the Keychain (`PeerIdentity`)
- **Traffic privacy**: constant-rate cover traffic option (`MeshShield`) —
  cover traffic only, no additional encryption claims
- **Routing intelligence**: battery/congestion-aware relay decisions
  (`MeshIntelligence`), pheromone-style path preference (`PheromoneRouter`)
